# 공통 환경과 데이터 준비

이 폴더의 Markdown 실습은 **Oracle AI Database 26ai의 PDB + Python 클라이언트**를 기준으로 정리했습니다. 원본은 23ai·26ai 환경의 노트북 예제입니다. VECTOR·ONNX·문서 필터·HNSW·Hybrid 지원과 API 인수는 사용할 RU에서 확인합니다. 실제 DB에 접속해 재실행한 검증은 수행하지 않았습니다.

## 1. 실행 위치 구분

| 구분 | 담당 작업 | 경로 예시 |
| --- | --- | --- |
| DB 관리자 / Oracle OS 계정 | PDB·계정·권한, 모델·원본 파일 적재, DB 디렉터리와 메모리 준비 | `/home/oracle/labs/data/docs`, `/home/oracle/labs/data/images` |
| Python 클라이언트 | 문서의 Python 코드, 질의 입력, 표·이미지 출력, LangChain 호출 | 저장소의 `similarity_search` 폴더 |
| Ollama 서버 | `llama3.2` 등 실제 설치한 생성 모델로 응답 | `http://service-ollama:11434` |

`BFILENAME`은 DB 서버의 DIRECTORY 객체가 가리키는 파일을 읽습니다. Python의 `./data/images/val_data`는 Python 작업 디렉터리에서 읽습니다. 같은 저장소 파일을 사용해도 두 경로가 자동으로 연결되지는 않습니다.

## 2. Python 환경

`similarity_search` 폴더에서 다음 패키지를 준비합니다. 폐쇄망에서는 호환되는 wheel과 의존 패키지를 별도로 반입합니다.

```shell
python -m pip install oracledb pandas pillow matplotlib langchain-core langchain-ollama
```

문서 검색만 수행한다면 `oracledb`와 `pandas`가 기본이며, 이미지는 Pillow·Matplotlib, RAG는 LangChain 관련 패키지를 사용합니다. Jupyter는 선택 사항입니다. 각 문서의 Python 블록을 같은 Python 세션에서 순서대로 실행하거나 하나의 `.py` 파일로 모아 실행합니다. SQL 블록은 SQL*Plus·SQLcl 등에서 별도로 실행합니다.

공통 모듈 [user_functions.py](user_functions.py)는 코드와 같은 폴더 또는 Python 모듈 검색 경로에 두어야 합니다. `import_ipynb`·OML4Py를 설치할 필요는 없습니다. 모델을 ONNX로 변환하는 별도 작업에는 해당 변환 도구가 필요할 수 있습니다.

## 3. DB·권한·모델 준비

관리자는 실습 계정과 테이블스페이스 quota를 준비하고, 필요한 시스템·객체 권한을 부여합니다. 아래는 이미 생성된 `LABADMIN` 예시입니다. 계정·테이블스페이스는 실제 환경에 맞게 바꿉니다.

```sql
-- 관리자: 대상 PDB에서 실행
GRANT CREATE SESSION, CREATE TABLE, CREATE PROCEDURE TO LABADMIN;
GRANT CREATE MINING MODEL TO LABADMIN;
GRANT EXECUTE ON DBMS_VECTOR TO LABADMIN;
GRANT EXECUTE ON DBMS_VECTOR_CHAIN TO LABADMIN;
ALTER USER LABADMIN QUOTA 200M ON USERS;
```

문서 추출·하이브리드 실습은 Oracle Text 구성과 필요한 패키지 실행 권한도 확인합니다. 하이브리드 인덱스 준비는 [해당 실습](3.Hybrid_search.md)을 따릅니다. HNSW를 만들 때는 관리자가 CDB·PDB의 `VECTOR_MEMORY_SIZE`와 실제 메모리 여유를 확인합니다. 정확 검색만 확인할 때는 HNSW 생성 단계를 건너뛸 수 있습니다.

| 실습 | DB에 준비할 모델 |
| --- | --- |
| 문서 유사도·문서 RAG·테이블 RAG·Hybrid | `MULTILINGUAL_E5_SMALL` |
| 이미지–이미지 | `CLIP_VIT_LARGE_PATCH14_IMG` |
| 텍스트–이미지 | 위 이미지 모델과 같은 계열의 `CLIP_VIT_LARGE_PATCH14_TXT` |

모델명은 예제에서 지정한 DB 객체 이름입니다. 이름만 지정하면 모델이 다운로드되는 것은 아닙니다. 임베딩에 필요한 전처리·후처리를 포함한 ONNX 모델을 먼저 적재합니다. 모델 파일은 이 저장소에 포함되어 있지 않습니다. [Oracle ONNX 모델 적재](https://docs.oracle.com/en/database/oracle/oracle-database/26/vecse/import-onnx-models-oracle-ai-database-end-end-example.html), [CLIP 변환·임베딩 예제](https://docs.oracle.com/en/database/oracle/oracle-database/26/vecse/generate-multi-modal-embeddings-using-clip.html)

문서·질의의 모델, 차원, 거리 척도와 전처리를 일치시킵니다. E5 계열처럼 질의·문서 접두어가 필요한 모델은 적재한 모델의 전처리와 학습 지침을 확인해 양쪽에 일관되게 적용합니다. 전처리를 바꾸었다면 저장 벡터도 다시 생성합니다.

## 4. 원본 파일과 테이블 적재

[데이터 준비 SQL](similarity_search_config.sql)은 DIRECTORY 생성과 문서·이미지·보도자료 샘플 데이터를 포함합니다. **관리자 DDL과 실습 계정의 테이블 생성·적재를 구분해 필요한 구간만 실행합니다.** 기존 테이블이 있는 환경에 전체 파일을 일괄 재실행하지 않습니다. SGA 변경이나 DB 재시작은 이 실습의 자동 실행 단계가 아닙니다.

| 자료 | 저장소 위치 | DB DIRECTORY 예시 | 대상 테이블 |
| --- | --- | --- | --- |
| 일반 문서 | `data/doc` | `DOCPATH` → `/home/oracle/labs/data/docs` | `DOC_STORE`, `DOC_STORE_CHUNKS` |
| 저장 이미지 | `data/images` | `IMGPATH` → `/home/oracle/labs/data/images` | `IMG_TBL` |
| RAG 문서 | `data/doc/rag` | `RAGDIR` → `/home/oracle/labs/data/docs/rag` | `RAG_TBL`, `RAG_TBL_V` |
| 보도자료 메타데이터 | SQL 파일의 INSERT 구문 | 사용하지 않음 | `BROAD_TBL` |

관리자는 원본 파일을 DB 서버에 복사하고 DIRECTORY를 생성합니다. 파일명은 SQL의 `BFILENAME`과 정확히 일치해야 하며 OS Oracle 계정이 읽을 수 있어야 합니다. 예를 들어 RAG 문서는 다음과 같이 준비합니다.

```sql
-- 관리자: 대상 PDB. 기존 DIRECTORY의 경로를 임의로 바꾸지 않습니다.
CREATE DIRECTORY RAGDIR AS '/home/oracle/labs/data/docs/rag';
GRANT READ ON DIRECTORY RAGDIR TO LABADMIN;
```

다른 DIRECTORY도 같은 방식으로 필요한 계정에 읽기 권한을 부여합니다. `CREATE ANY DIRECTORY`를 실습 계정의 기본 권한으로 부여할 필요는 없습니다. PDF·HWPX가 모두 같은 방식으로 추출된다고 가정하지 말고 문서별로 텍스트 추출을 먼저 점검합니다. 실패하거나 깨진 문서는 지원 형식으로 변환한 뒤 적재합니다.

## 5. 연결·데이터 확인

Python 코드의 접속 정보는 `ORACLE_USER`, `ORACLE_PASSWORD`, `ORACLE_DSN` 환경 변수 또는 실행 중 입력을 사용합니다. 비밀번호는 `getpass`로 입력할 수 있습니다. DSN 예시는 `DB호스트:1521/PDB서비스`이며, 실습 계정으로 대상 PDB에 접속합니다.

```sql
SELECT SYS_CONTEXT('USERENV', 'CON_NAME') AS pdb_name, USER AS current_user
FROM dual;

SELECT model_name, mining_function FROM user_mining_models ORDER BY model_name;
SELECT table_name FROM user_tables
WHERE table_name IN ('DOC_STORE', 'DOC_STORE_CHUNKS', 'IMG_TBL',
                     'RAG_TBL', 'RAG_TBL_V', 'BROAD_TBL');

-- 문서 실습을 선택한 경우: PDF 한 건의 추출 결과부터 확인
SELECT docno, DBMS_LOB.SUBSTR(DBMS_VECTOR_CHAIN.UTL_TO_TEXT(doc), 300, 1) AS text_preview
FROM doc_store WHERE docno = '10-3';
```

문서 한 건에서 텍스트 추출 → 청크 생성 → 임베딩을 확인한 후 전체 자료를 처리합니다. 새로 만든 청크 테이블의 행 수가 0이면 검색 단계보다 적재 오류와 원본 텍스트부터 확인합니다.

## 6. RAG에서 Ollama 연결

이 폴더의 RAG는 Select AI Profile 대신 LangChain 또는 `DBMS_VECTOR_CHAIN.UTL_TO_GENERATE_TEXT`를 직접 사용합니다. 두 경로의 접속 위치와 URL 형식을 구분합니다.

| 경로 | 호출 위치 | 설정 |
| --- | --- | --- |
| LangChain → Ollama | Python 클라이언트 | `OLLAMA_BASE_URL`, 기본 `http://service-ollama:11434` |
| DB REST → Ollama | DB 서버 | `OLLAMA_GENERATE_URL`, 기본 `http://service-ollama:11434/api/generate` |
| 생성 모델 | 양쪽 동일 모델로 비교 | `OLLAMA_MODEL`, 기본 `llama3.2` |

DB REST 호출은 관리자가 실습 계정에 대상 호스트의 네트워크 ACL을 준비해야 합니다. Python에서 호출된다는 사실만으로 DB의 호출 권한이 확인되지는 않습니다. HTTPS·인증을 적용한 서비스는 해당 Wallet·Credential 구성도 확인합니다. `host=local`은 이 예제의 인증 없는 내부 제공자 설정입니다. [Oracle 텍스트 생성 API](https://docs.oracle.com/en/database/oracle/oracle-database/26/vecse/utl_to_generate_text-dbms_vector_chain.html)

## 7. 재실행과 결과 해석

- TRUNCATE, 벡터 컬럼 초기화, 인덱스 삭제는 기존 실습 데이터를 변경합니다. 본인 실습 객체인지 확인하고 필요한 단계만 재실행합니다.
- DDL은 암묵적으로 커밋될 수 있습니다. 원본 데이터 적재와 벡터 생성은 각각 완료 후 건수·NULL 여부를 확인합니다.
- 정확 검색은 비교 기준이고 근사 검색은 속도와 검색 재현율을 함께 확인하는 대상입니다. HNSW 인덱스 생성과 근사 검색 SQL 사용은 별개의 단계입니다.
- COSINE 거리는 작을수록 가깝고, `1-distance`는 표시용 유사도입니다. 하이브리드 결합 점수·모델 정확도와 같은 수치로 해석하지 않습니다.
- 원본 노트북의 텍스트·HTML 실행 로그는 문서에 반복 수록하지 않았으며, 이미지 출력 5개는 과거 실행 예시로 보존했습니다.
